# NC22 = NC21 + ClearGroup no longer rejects wild bandits as owned_target (row IMM-14-d)

Cause: `IsProtectedActivityTarget` (ActivityPolicySupport.cpp) treated `target->getMySlaveOwner().serial != 0` as proof of ownership. NC20 diag (lane i5, evidence `C:\KenshiTestRuns\imm26-5090-i5\14d\run-nc20\cleargroup_member_lines.txt`): of 5 freshly spawned Dust Bandits (harness `createRandomCharacter`, all hostile, visible, pathExists) Prenn and Othra had protected=1 protReason=owned_target while Wulf/Doran/Falt had protected=0. So the owner handle serial is non-zero for some spawned wild bandits that are not slaves; a bare non-zero handle is not ownership (the exact engine reason for the stray value is not provable offline; the engine getter was not decompiled).
Fix (`ActivityOwnership.h`, pure `Decide`): a person is owned only when the owner handle is corroborated by `isSlave() != NOT_SLAVE` or `isChainedMode()`; a character in a prison cage (`inSomething==IN_PRISON`) is protected as `captive_target`; animals keep the strict rule (any owner handle = `owned_target`, then ProvenWild). Order unchanged: player/ally/same faction, ceasefire/truce, ownership, animal wild proof, non-hostile.
Diagnostic: `ACTIVITY_CLEARGROUP_MEMBER ... memberY= actorY= ownerSerial=<n> slaveState=<0..3> chained=<0|1> prison=<0|1> animal=<0|1>` (before dist2d).
Operator expects for the 5 bandits: all `ACTIVITY_CLEARGROUP_MEMBER ... hostile=1 protected=0 protReason=` (Prenn/Othra may show ownerSerial=<non-zero> slaveState=0 chained=0 prison=0); `set=5/5`, probe `agreedTargets` lists 5 serials. If a member still shows protected=1 the line now names which of owner/slave/chained/prison caused it.
