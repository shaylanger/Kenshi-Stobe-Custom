# NC21 = NC20 + the participation proof binds (row IMM-13-c `participation_bound=0`)

Cause (evidence, no game run needed): `Character::getInstanceID()` is `RootObject::getInstanceID()`, which returns NULL for every Character (only `Building` overrides it; in kenshi_x64.exe the KenshiLib RVA 0xD1EA0 is at 0xD1EE0 in the lane exe and is `xor eax,eax; ret`, next to `getLayoutInstanceID` = `lea rax,[rip+empty string]; ret`). The InstanceID uid therefore never exists for an NPC or the player. The whole mod already identifies characters as `hand_<serial>` (`Context.cpp GetStorageIDFor`, snapshot `"id"`, server `core_npc.storage_id`; the lane prompts/effects show only `hand_...`). `ParticipationEvidence::Begin` demanded a non-empty uid ("never use hand_ as durable identity"), so `participation_bound` was 0 on every trip (never 1 in any lane log: 4080 13-c, 5090 23-a, 19-d) and the server award said `participation_proof_missing_or_unqualified`.

Fix (native only, Shay decision 2026-10-16 "server hand_<serial> id fallback"): the proof identity is exactly what the server stores: uid if the engine ever gives one, else `hand_<serial>` (`ParticipationIdentity.h`, pure). Identity stays pinned: `Sample` still requires the exact actor/partner handle and recomputes the id each sample (change => unbound). Qualification thresholds (4 samples, 30 s span, <=35 u separation, <=20 u/s+5 per step, actor/partner distance >=30, endpoint progress >=30) are untouched. Server: no change (`lib/relationship_participation.php` already accepts any 1..180 char storage id and sets `storage_alias=hand_<serial>`; `server_hand_proof_check.php` 3/3 + the existing wp13c regression 14/14 in /root/imm26/compose).

Also in NC21:
- `Begin` takes the actor `Character*` Start already holds (no dependence on the handle cache for the actor).
- Bind result is logged: `NATIVE_TRAVEL_START ... participation_bound=1 participation_why=ok_hand_fallback participation_ids=hand_<npc>,hand_<player>`; a failed bind names the cause (`actor_unresolved`, `partner_unresolved`, `same_actor_partner`, `world_agreement_or_task_empty`, `actor_no_identity`, `partner_no_identity`, `same_identity`, `exception`). The lazy route-controller bind logs `NATIVE_TRAVEL_PART_BIND`.
- Terminal `NATIVE_TRAVEL ... participation_qualified=0|1 participation_diag=samples:N,span:S,best_span:B,actor_d:,partner_d:,progress:,max_sep:,brk_sep:,brk_jump:,brk_gap:,brk_state:,brk_scope:,brk_other:` so a non-qualifying walk names its reason (separation / teleport jump / gap) without a rig.
