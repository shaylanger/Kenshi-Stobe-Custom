## 1. Row 25-b FIX (behaviour change): natural mine node product without a ProductionBuilding
Cause (NC11 diag): iron node special=27, inventory present, `Building::_NV_getProductionBuilding()` NULL => `ExactSection`/`MineSourcePermitted` always `exact_output_unavailable`.
Now (`ActivityPolicySupport.cpp`, both `src` and `legacy-v1`; pure decision in new header `ActivityMineProduct.h`):
- `NaturalOutput(b,item,how,clause)`: special 27, not destroyed, no production building. Product = the single item id stored in the node inventory (mixed or null items fail closed), else the single ITEM-type reference in the node GameData reference lists (`objectReferences`, `ptr` resolved). Expected item (agreement resourceId) must match. Output section = the section holding the stored items (all items must be in it), or the only section when the inventory is empty (several = `natural_output_section_ambiguous`).
- `ExactSection` uses it for such nodes; `MineSourcePermitted` returns `item=<product>` instead of `exact_output_unavailable`.
- Lease (`MineLease.natural`): a natural node has no `_NV_updateOutput` hook, so output growth is polled in `Check`/`ConfirmMineOutputTaken` and credited only while the lease actor is alive and within 60 units (horizontal) of the node; any other change still invalidates the lease. Production-building mines are untouched.
- Limits: compile-verified only (game types); if the node inventory is empty AND its game data has no ITEM refs the clause is `natural_product_unresolved` and the log lists the node's reference lists (`lists=name:count,...`) so the next round can read the real data field.
