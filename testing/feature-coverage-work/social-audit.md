# NPC/social immersion audit: requirements 1–10

Scope: read-only audit of source, existing tests, and recorded receipts. No implementation, rig, or queue work was performed. Requirement wording below is copied verbatim from the assigned list.

**Release boundary:** the latest shared checkpoint records the composed server candidate under runtime/copied-save release holds; the current AEF game build excludes server-side social/age changes. The seven-social module/release fixtures below are exact-hash offline evidence, not proof that those modules are installed or working in the current game. See testing/HANDOFF.md and pending-fixes/npc-social-additions/STATUS.md.

1. **Personal boundaries you can learn: an NPC might dislike slavery, refuse theft, or avoid a faction; discover principles through conversation.**
   - Implementation: pending-fixes/npc-social-additions/boundaries/npc_personal_boundaries.php; composed source copies under pending-fixes/activity-goals-main/release-candidate-runtime-validation-20261013/server/live/lib/npc_personal_boundaries.php. Guidance is grounded in enabled profile sources and preserves unknown values; it does not establish durable learned principles by itself.
   - Evidence: SOCIAL-ADDITIONS-RELEASE, 37-case offline fixture, including profile-source/disabled-section/narrator checks: pending-fixes/rig5090-validation/social-additions-5090-20261013.md and pending-fixes/rig4080-validation/social-additions-release-4080-runtime-20261013.md. Boundary live packet: pending-fixes/npc-social-additions/operator-packets-20261013-r5/BOUNDARIES.md.
   - Status: PARTIAL. The profile-grounded prompt behavior has offline coverage; neither discovery through an actual conversation nor persistence/carry-forward is proven. The recorded narrow 4080 boundary acknowledgment does not prove those behaviors (pending-fixes/rig4080-validation/STATUS.md).
   - Blocker / next test: current release is not installed. On the exact composed candidate, test a stated slavery/theft/faction principle, a smaller acceptable compromise, a correction, and a later recall; inspect prompt and any action dispatch separately.

2. **Remember how you treated other people: witnessing help/mistreatment influences opinion; unwitnessed acts require believable rumor.**
   - Implementation: native event/witness payload in components/STOBE/src/SocialEventProtocol.cpp; relationship rules in docs/RELATIONSHIP_SYSTEM_DESIGN.md and server relationship interpreter/store. The design explicitly says no rumor system is required in the first release (RELATIONSHIP_SYSTEM_DESIGN.md, §5), so that requested behavior is absent from the documented scope.
   - Evidence: REL SR24 (conscious friend witness shares victim’s feeling) PASS; SR25 (asleep witness has no effect) PASS; SR27 (dialogue insult listener data) PARTIAL because dialogue listener data was not built. Results and run labels are in docs/REL_FINAL_REPORT.md, rows SR24–SR27; design test row SR27 is in §8.
   - Status: PARTIAL. Witnessed harm has a real in-game pass and asleep/no-witness has a negative control. Witnessed help as a social observation and believable rumor for unwitnessed events are not demonstrated; rumor is explicitly out of scope in the design.
   - Blocker / next test: rumor needs an authored evidence source and freshness/attribution rules. Then test a witnessed event, an unwitnessed event with a believable one-hop rumor, and an unwitnessed event without rumor; reject omniscience and recursive spread.

RELATIONSHIP-CONTEXT PASS, 26 offline assertions, covers listener/affinity selection and context wording, not live database loading or model behavior: pending-fixes/rig5090-validation/relationship-context-5090-20261013.md.

   - Blocker / next test: define/verify the typed relationship facts and scope, then test two NPCs with a known tie and debt through defense, trust language, referral, and refusal; include a control with no known tie.

On 4080, CD5 refused an absolute secrecy guarantee but added an unsupported “public area” claim; the audit classifies this as a limit, not a privacy pass (pending-fixes/rig4080-validation/complex-dialogue/CD5.md and CD5-privacy-prompt.txt).    - Blocker / next test: use exact current build with fresh native observations in a private scene, a scene with a visible guard/coworker, and stale/missing audience data. Ask about the same sensitive act and verify only observed listeners shape the response; do not infer hearing from distance alone.
