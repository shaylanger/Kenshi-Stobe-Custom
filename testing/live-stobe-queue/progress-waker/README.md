# Live Stobe progress waker

`tools/automation/live-testing-waker.ps1 -Run` is the persistent monitor. It inspects the pinned row and native log for each rig every 120 seconds, writes current state atomically to `state.json`, and appends sequenced alerts to `events.jsonl`. `targets.json` is schema 2 runtime data; each tick validates it against the strict phase/identity schema and trusted path/command guards. General row phases use the small generic allowlist. UI-only KAH phases (`A_open_pending`, `A_read_pending`, `A_screenshot_pending`, `A_done_B_read_pending`, `B_select_pending`, `B_read_pending`, `return_A_read_pending`, `ABA_complete_receipt_pending`) are accepted only when the row has a real `uiActionId` and positive `uiGeneration`. A UI transaction is never placed in the chat `request` field. For an active UI row, the matching rig entry in `operators.json` must carry `uiProgress: { actionId, generation, stage, readback }` from observed KAH output. The action and generation must match the target; stage must be one of the supported UI stages; readback must be non-empty and at most 512 characters. The frozen `targets-schema-fixture.json` and self-tests are the reviewable schema contract. Operators and the monitor refresh `targets.json` when the active row/request/action changes and `operators.json` after verified status/progress updates. A setup failure before KAH creates a request may use `receiptOnly=true` only for an idle `row=none`, `phase=complete_awaiting_next` target with `lastCompletedRow`, no request/action IDs, and an exact pinned receipt SHA/content. The receipt must be under its rig's approved evidence root; the shared live-queue root is allowed for a 4080 receipt only with a `-4080-` receipt filename. This exception cannot identify or track an active row. Other idle terminal targets retain `lastCompletedRow` and either `lastCompletedRequest` or `lastCompletedActionId` plus `lastCompletedGeneration`.

Start it hidden from the workspace root:

```powershell
$p = Start-Process powershell.exe -WindowStyle Hidden -PassThru -WorkingDirectory C:\KenshiModding -ArgumentList @('-NoProfile','-ExecutionPolicy','Bypass','-File','C:\KenshiModding\tools\automation\live-testing-waker.ps1','-Run')
```

The process writes its PID and heartbeat into `state.json`; after the atomic state write, it appends one `TICK_COMMITTED` event per rig carrying that snapshot heartbeat and row identity. The monitor must ACK both matching tick events before reporting a paired tick. It consumes JSONL events with the race-safe consumer:

Event appends retry only failures to open the log. Once a writer opens the file, a write/flush failure latches the producer closed; it writes the failure to stderr and does not append a second event that could corrupt the tail. On restart, after acquiring the single-producer lock, the waker takes exclusive file ownership, validates complete JSONL records, and truncates only an invalid or unterminated trailing suffix before resuming from the last valid sequence. Complete prior events are preserved. A held reader or malformed interior record prevents recovery and the producer exits without modifying the log; resolve the reader/corruption before restarting. The partial-write/restart self-test verifies this behavior against two preserved prior events.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File C:\KenshiModding\tools\automation\consume-live-testing-event.ps1 -EventsPath C:\KenshiModding\testing\live-stobe-queue\progress-waker\events.jsonl -CursorPath C:\KenshiModding\testing\live-stobe-queue\progress-waker\consumer.cursor -ReadyPath C:\KenshiModding\testing\live-stobe-queue\progress-waker\consumer.ready -InitialCursor <last-consumed-seq> -Timeout 110
```

The consumer arms its file watcher before atomically publishing `consumer.ready`, then rereads the append-only event log for every sequence greater than its durable cursor before blocking. A returned `ACK sequence=N` advances `consumer.cursor` atomically, so restarting after a wake neither skips a pre-arm append nor acknowledges the same sequence twice. Re-arm after `TIMEOUT`; after every wake, also read `state.json` to inspect the paired 4080/5090 snapshots, since unchanged healthy rows need not emit an event. Message root and the queue supervisor immediately for `ROW_STALLED`, `GAME_PROCESS_DEAD`, `OPERATOR_NOT_ACTIVE`, `OPERATOR_HEARTBEAT_STALE`, `OPERATOR_STATUS_UNKNOWN`, `DEPENDENCY_BLOCKED`, `RIG_OBSERVATION_BLOCKED`, `WAKER_ERROR`, `COMPLETE_AWAITING_NEXT`, or `IDLE_LANE`. `IDLE_LANE` evidence carries the supervisor's current next-candidate note so an idle rig is surfaced even before a new row is dispatched. A missing operator record means liveness is unverified and requires a monitor check; it is not treated as a dead agent. The queue supervisor and sole rig operators own queue edits and starts. Completion events include the next candidate; it must be marked READY before an operator queues it. Never start filler to mask an idle event.

Chat progress requires a changed native event line containing the exact current request ID and a recognized chat/backend stage. UI progress requires the exact `uiActionId`, generation, supported stage, and non-empty readback from the operator snapshot. The initial matching evidence is only a baseline. The cursor is a SHA-256 digest of the full matching evidence, so changes after character 240 still count; state schema v3 retains UI identity alongside chat request cursors. Game PID, native log mtime, unrelated events, receipts being edited, and generic agent activity do not count as row progress. An existing terminal receipt yields a terminal event and `COMPLETE_AWAITING_NEXT`; an active row without its exact identity-correlated evidence becomes dependency-blocked or stalled. Game/SSH checks are read-only. Runtime target validation restricts rig/source pairing, KAH row IDs, chat/UI identity, receipt paths to their rig-specific workspace evidence roots, and next-candidate text length. The 4080 host alias, hostname, SSH config and executable, i3 log path, and game executable are all canonicalized before SSH runs. On 4080, process state is `dead` only when the protected remote CIM query succeeds and finds no matching i3 executable; a failed query stays `unknown`, and a 4080 PID is never checked against the local machine's PID table.

Before changing a row target, verify the request/receipt/log path with the sole operator or queue supervisor. `operators.json` is a liveness input; status `running` or `active` older than 240 seconds is stale, and a `stopped` or `completed` operator is reported inactive. The watcher never drives a game, inbox, backend, save, service, or queue.

Run `powershell -NoProfile -ExecutionPolicy Bypass -File C:\KenshiModding\tools\automation\consume-live-testing-event.ps1 -SelfTest` after consumer edits and `powershell -NoProfile -ExecutionPolicy Bypass -File C:\KenshiModding\tools\automation\live-testing-waker.ps1 -SelfTest` after waker edits. These synthetic tests do not contact either rig.
