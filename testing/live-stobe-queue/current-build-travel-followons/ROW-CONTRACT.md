# Executable P0 travel follow-on row contract

These rows extend, but never edit or replace, the frozen `current-build-travel-driver/` row. They must invoke existing isolated-i3 `stobe-auto` handlers and retain raw request/native receipts. They must not use teleport, direct `TRAVEL_LOCATION`, injected native orders, SQL writes, or mutate trip state outside the ordinary chat/parser/policy/dispatch path.

Each row is a standalone executable with a unique `OUT` claimed atomically before its first handler call. It requires exact `RIG=5090|4080`, `KAH_INSTANCE=3`, expected `KENSHI_DIR`/`KAH_DIR`, exact current NPC display name and serial, fresh preflight/build/save/session receipts, and a native log path. Every chat request is bounded by timeout/polling and must wait for `CHAT_THREAD: Queued N streamed chat lines and N action lines` plus all queued `NPC_SAY` records before interpreting the reply. Read actor state from exact `stobe_state #serial/index`; the `ai` values are nested. Preserve exact native action identity and destination correlation.

The row result class is explicit: `FAIL setup` for missing/stale pins, fixture, actor, route or initial world state; `FAIL evidence` for incomplete or mis-scoped receipts; `FAIL product` only for a fully evidenced contract violation; `PASS` only for the assertions the row actually observes. Never infer trip agreement from dialogue, execution from ACCEPTED, arrival from proximity, or cleanup from END/cancel text. If the current build exposes no safe supported reader/trigger for a required durable lifecycle assertion, mark only that assertion `UNSUPPORTED` and do not claim full lifecycle coverage.

Deterministic mechanical replies may use the reviewed private provider fixture only through the existing scoped `NEG_TEST_INJECT` chat step (`step.provider_fixture_id`). The exact fixture scope must bind row ID, current NPC name, player speaker, and exact message; verify its one-shot fixture-hash/request-ID receipt fired. Fixture output continues through the normal reply parser, consent policy, commitment store and native dispatch. Keep this distinct from live-model dialogue, and do not fabricate provider metadata or bypass the gate.

Before sharing a row with a rig owner, provide its exact SHA-256, a meaningful mocked-handler selftest, independent exact-byte review, exact required receipts/fixture IDs, supported assertions, and known unsupported assertions. Rig owners retain all physical execution and install ownership.
