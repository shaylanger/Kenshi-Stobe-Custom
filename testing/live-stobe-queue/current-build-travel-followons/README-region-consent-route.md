# P0 coarse-region consent to grounded travel

`region-consent-route.sh` is a standalone two-turn row. Turn one asks the exact NPC to offer the observed broad region, explicitly withholding travel consent. The complete reply and correlated backend record must create a same-region conceptual `SUGGEST` while `travel_decision` remains `NONE`; the complete native stream must report zero action lines and contain no `ACTION_EXEC`. Turn two sends the only player consent: `I agree to go to <REGION> as a broad area.` It does not name or separately accept an endpoint. The selected handler must prove a fresh, scoped successful no-active-trip read, resolve a region-matched endpoint from the current actor-scoped native candidate, then accept through the ordinary travel lifecycle. The completed reply identifies that endpoint as a rough starting point and does not promise route safety or what will be found. The exact actor/serial must emit exactly one ordinary native `TRAVEL_LOCATION` to that label and endpoint XYZ. Nested `stobe_state.ai.destination` must match the action coordinates, with `moving=true`, `destination_reached=false`, and `path_failed=false`; at least two consecutive closer intervals and 5m net progress are measured from the exact actor position captured immediately before consent.

The row uses only `stobe-auto status`, `stobe_ping`, `where`, `stobe_state`, and normal `stobe_say`. It never invokes a direct action handler, writes the ledger, injects provider content, teleports, or changes trip state directly. It saves both full native deltas, backend deltas, exact request IDs, endpoint proof, action event and progress samples in `OUT`. Each backend record must bind that turn's exact native request ID, row, NPC display name and serial, player speaker, and full submitted message. The proposal record binds `region_plan_decision=SUGGEST`, the exact region, and `travel_decision=NONE`; the consent record must expose structured `destination_point` and `regional_goal` values. Their IDs, labels, actor serials, region, and provenance must agree; finite XYZ must come from `destination_point` (`source=native_local`) and the region endpoint source must be `current_actor_scoped_native_candidate` (or the reviewed server receipt source). Region evidence must be `native_spatial_region` or `npc_known_town_region`. The current-turn `regional_goal` must include `trip_read_succeeded=true`, explicit `prior_trip_status=none`, `trip_read_scope={campaign_id,actor_id,speaker_id}`, its matching SHA-256, actor/speaker serials and gamets for that exact trip-read scope, and `ordinary_order_validation=passed` with its game-time marker. The scope digest follows the producer’s PHP `json_encode` insertion order (`campaign_id`, `actor_id`, `speaker_id`); the row hashes the exact received compact JSON object in its received key order and rejects a digest for a different order. Preflight binds the expected campaign and player serial. The native success event must identify exact action label, actor, serial, and integer XYZ; coordinates must match the selected endpoint within 1m (to allow native integer rounding), and nested `ai.destination` must also match within 1m. Every progress sample must carry boolean `moving`, `destination_reached`, and `path_failed` fields; at least one must show `moving=true` and `destination_reached=false`, and every one must show `path_failed=false`. Nonnumeric or non-finite positions/destinations fail as evidence. Missing or unbound proof is `FAIL evidence`. Wrong turns/decisions, a pre-consent action, wrong actor/region/endpoint, duplicate or extra action, path failure or mismatched native destination are `FAIL product`.

## Exact source and current-build gates

The current integration overlay is still a candidate and is not automatically executable. The row refuses KAH calls until an `INTEGRATION_RECEIPT` proves that the exact reviewed candidate is installed and served by the current loaded build, and that its reviewed contract is one coarse-region consent with proposal-only behavior before consent. The receipt must include `candidate_sha256`, `review_status:"CLEAR"`, `installed:true`, `served:true`, `integration_build_sha256` equal to preflight `build_sha256`, `movement_consent_contract:"one_coarse_region_acceptance"`, `endpoint_requires_separate_consent:false`, `preconsent_proposal_only:true`, and `endpoint_proof_source:"current_actor_scoped_native_candidate"` (or `reviewed_server_receipt`). `INTEGRATION_SHA256` is an independent exact-review pin and must equal the receipt pin. Offline fixture PASS or candidate presence alone cannot satisfy these gates.

Fresh JSON files are required through `PREFLIGHT_RECEIPT`, `REGION_RECEIPT`, `INTEGRATION_RECEIPT`, and the preflight-pinned `model_readiness_receipt_path`. Every file binds `rig`, `instance:"3"`, `npc_name`, numeric `npc_serial`/`npc_index`, `player_speaker`, `save_id`, `session_generation`, and `build_sha256`. Preflight also binds `phase:"world"`, `paused:false`, `input_isolation:"ON"`, exact `native_log`/`backend_log`, `campaign_id`, `player_speaker_serial`, model receipt path and SHA-256. The opened, hash-checked model receipt must bind the same identity/session/build and have `review_status:"CLEAR"`, `model_status:"READY"`. Region receipt carries exact `region_name`, `region_source` and the same live bindings. All receipts must be fresh (600 seconds by default). `OUT` must be a newly atomically claimed directory with an existing parent.

Only isolated instance 3 is allowed: 4080 (`KENSHI_DIR=/c/KenshiInst/3`, `KAH_DIR=C:\\KenshiInst\\3\\mods\\AutomationHarness`) or 5090 (`KENSHI_DIR=/mnt/d/KenshiInst/3`, `KAH_DIR=D:\\KenshiInst\\3\\mods\\AutomationHarness`). Source `tools/automation/rig-env.sh` for the selected route. This row uses a live-model turn and permits no provider fixture. Durable trip ledger lifecycle, session-generation reader beyond externally bound preflight, arrival, completion and cleanup are not asserted.
