# Physical-rig offline validation queue

Purpose: keep reviewed, isolated offline checks moving on the physical 4080 and 5090 without launching Kenshi or touching saves, services, production data, or installed builds. This queue is owned by the coordinator; the named rig operator updates each row immediately after a start, result, failure, or blocker.

## Queue rules

- One dedicated operator owns each physical rig while this queue has eligible work: `/root/4080_reboot_runtime` is the trusted physical executor for `DESKTOP-NQQPA73` (with `/root/rig4080_queue_operator` coordinating/auditing); `/root/rig5090_queue_operator` is the current physical executor for `DESKTOP-JFLPK99`.
- Run only the exact candidate/fixture hashes that have an independent CLEAR review and a runnable isolated fixture. Check all manifest dependencies before running. A PASS is only offline fixture/lint evidence; do not describe it as gameplay validation.
- Keep the physical rig's `C:\KenshiTestRuns\inflight\<rig>-<test>` marker set during the run and clear it on exit. Record host, exact command, PID/output path, start/end, hashes, lints, one `RESULT` line, and receipt before marking DONE.
- Before the current item ends, the operator must have selected the next eligible item from this file or the documented issue register. Do not repeat an unchanged exact PASS. Do not enqueue known-failing hashes, unreviewed candidates, or game/service tests in this offline queue.
- Check process and marker progress at least every two minutes. On a missing process, stale output, hash mismatch, or route failure, record the blocker, stop retrying that same path, and take the next independent eligible item.
