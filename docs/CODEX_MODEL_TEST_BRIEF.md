## Preparation and eventual execution interface

The Codex runner interface is:

```text
python tools/model-test/codex_bench.py prepare <suite-dir>
python tools/model-test/codex_bench.py preflight <suite-dir>
python tools/model-test/codex_bench.py run <suite-dir> <run-id> --execute
python tools/model-test/codex_bench.py status <suite-dir>
python tools/model-test/codex_bench.py record <suite-dir> <run-id>
python tools/model-test/codex_bench.py recheck <suite-dir> <run-id>
```

Only `run ... --execute` launches a paid task. Prepare/preflight/status are setup and inspection. Before any execution, preflight must verify the frozen world and database, suite order/config, allowed model and effort, and price metadata. Stop on a missing or invalid prerequisite; never fall back to live paths. Keep each retry as a new `runs/<id>/attempt-NN/` receipt and preserve failed attempts. The canonical unedited final answer is `runs/<id>/report.md`; append the run measurement to `runs.tsv`. The Codex recorder owns that TSV's full schema; `mt.py blind/report` require at least the `run`, `token_usd`, `wall_s`, and `violation_flags` columns. Do not use `mt.py rec` for Codex runs because it parses Claude transcripts.
