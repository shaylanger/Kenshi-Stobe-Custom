- **Session continuity (Shay, 2026-10-10; a session switch lost agents and a half-finished file):** (1) **Context-limit handoff is ordered by the hook:** at 300k the context-meter hook (project override `.claude/context-meter.project.ps1`) gives the exact steps: start nothing new, agents write their status, update HANDOFF.md + commit, `tools/automation/handoff-ready.ps1 "<note>"` (writes the marker; refuses if HANDOFF.md is stale), then the meter's `handoff` command opens the next session. Follow it to the letter. (2) **Agents report to files:** every subagent keeps `C:\KenshiTestRuns\agents\<name>.status` current with `tools/automation/agent-status.ps1 <name> RUNNING|DONE|FAILED|STOPPED-CONTEXT "<task>" "<latest step>" "<output paths>" "<next>"` (at start, at every milestone, and DONE/FAILED + result paths before its final report); its handoff goes to `C:\KenshiTestRuns\agents\<name>.handoff.md`, never only a scratchpad. Every agent prompt says so (`testing/AGENT_PROMPTS.md`). Delete a DONE status file once its result is in HANDOFF.md/the run log. (3) **Live state file:** update HANDOFF.md "Right now" the moment an agent starts/finishes, a batch starts/finishes, or a build is installed, not only near the limit, so a crash loses nothing. (4) **Detached batches are the unit of work:** long work (game rows, sweeps, renders, rig jobs) runs as a detached `run-batch.sh` job with `DONE` + `SUMMARY.txt`, not inside an agent's or the coordinator's conversation; write its out dir into its inflight marker (`echo <out> > C:\KenshiTestRuns\inflight\<name>`) so session-start reports it. (5) **Lean context:** view only the sheets a verdict needs (one at a time, not every frame), and record each verdict right away with `tools/automation/review-verdict.ps1 <row> PASS|FAIL|REJECT-SHEET "<sheet>" "<what was seen>"` so the image never has to be opened again; keep the RESULT-line / excerpt-only rules below.
- **State (no handoff files): read `testing/HANDOFF.md` first.** It holds the current checkpoint (m49, 2026-10-06), what is running, installed builds on both rigs, what each mod owns, status per mod, next work and the run recipes. Handoff files are retired (all deleted 2026-10-06): never write a separate handoff; update `testing/HANDOFF.md` "Current state" at every milestone and before a session ends. In short: KenshiFP decoupling done (all goal/action logic now in Stobe, KenshiFP = first-person only); FP combat open rows in `components/KenshiFP/docs/COMBAT_TEST_PLAN.md` (context `FP_COMBAT_COORDINATION_CONTEXT.md`, worked on directly on main); nothing waiting on Shay.

- **Index of all tests:** `MASTER_TEST_PLAN.md` (coordinator is the only writer). STOBE items: `STOBE_full_test_plan.md` (open items only, numbered from 1; next number in its header). Run logs: `archive/test-run-<date>-m<n>.md` (newest `archive/test-run-2026-10-06-m49.md`). Roles, loop, scenario format: `testing/README.md`.
- **GOAL (Shay's direct order, 2026-10-03):** the coordinator builds, tests, validates and fixes EVERYTHING, with no back-and-forth. If testing or validating anything needs a handler, harness command, test switch, hook, log line, driver or other code that doesn't exist, BUILD IT (yourself or via subagents), then run the test. Never report a row as blocked / "needs setup" / "missing code". Loop test → fix → build → install → retest until nothing testable is left, then close Kenshi and give Shay ONE final summary. Contact Shay only for real decisions, asked together once while work continues. Memory `coordinator-builds-everything`.

- **Subagents (Shay, 2026-10-10; replaces the 2-helper cap of 2026-10-03):** no fixed cap: the coordinator decides how many agents a task needs, and uses more whenever they make the work go faster (parallel fixers, one operator per rig, lab builder + lab maintainer, ...). Keep each agent on a clear scope with its own files so agents don't collide, and stop agents as soon as their queue is empty.
- **Naming:** plan items are plain numbers ("item 7"); old numbers ("was 79") only for tracing. Fixed and confirmed items get deleted from the plan (a line in the run log).
- **No manual validation:** Claude runs the whole loop alone (launch, test, fix, build, install, relaunch). A pass means real game state changed (status files, logs, inventories, events), never just the words. Rows only Shay can judge (sound, feel, tooltips) wait in MASTER section 2.
