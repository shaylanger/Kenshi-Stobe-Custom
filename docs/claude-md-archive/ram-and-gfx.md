- **RAM budget (Shay, 2026-10-04; updated 2026-10-09: the PC now has 48 GB, was 31 GB at ~90% use; ~22 GB free with Kenshi + WSL running, so RAM is no longer tight):** Kenshi and WSL (vmmem) are the two big users. Parakeet speech-to-text (~3.2 GB in WSL, started by `/etc/start_env`) stays stopped unless a test needs voice input (start it for that batch, stop it after). PocketTTS (`audiocpp_server`, ~1.4 GB) stays stopped too unless a batch tests audio/TTS, provided NPC replies still arrive quickly with no new errors without it (check once; if they stall or error, keep it running and note why here). WSL cap `memory=14GB`, `swap=8GB` in `%UserProfile%\.wslconfig` (2026-10-11, ram-fix: this Windows 10 build never shrinks vmmem, `autoMemoryReclaim` is ignored, drop_caches doesn't help, so vmmem grows to the cap and stays; at 24 GB it held 20 GB while WSL used 2-3 GB and lane 5090c ended lists on RAM CRITICAL with 3 Kenshi at ~10 GB each; 8 GB thrashed under parallel lab jobs). Apply with `tools/automation/wsl-restart.ps1` (Kenshi closed, no WSL run-batch; kills every WSL lab job: note the agents first; it also stops voice, starts cache-trim, turns STOBE off; `-Stobe` keeps it on). The lane memory guard's HOLD/CRITICAL lines say `VMMEM BLOAT` when vmmem >= 2x WSL used + 4 GB. WSL page cache: `tools/automation/wsl-cache-trim.sh start|stop|status` (WSL root, started by /etc/start_env; drops clean page cache every 120 s when over 1.5 GB so vmmem returns RAM; Shay 2026-10-10). Graphics-only mods that tests don't need (Dust + its effect DLLs, ReShade `dxgi.dll`, HD textures if measured worth it) stay off for automated runs, toggled by rename like `mem-ab.sh`, with a one-command restore for when Shay plays; never touch data mods the fixtures depend on.
  - **Test launches on the 5090: windowed, on DISPLAY2, never in the foreground (Shay, 2026-10-08; m72 ran exclusive-fullscreen on DISPLAY2 and interrupted him).** `tools/automation/kenshi-ctl.ps1 launch|restart` (default `-Monitor DISPLAY2`, background + input isolation) first switches `kenshi.cfg` to `Full Screen=No`, `Video Mode=1600 x 900` and saves Shay's values in `C:\KenshiTestRuns\kenshi.cfg.play`; windowed + background is the requirement, the monitor a preference (Shay): DISPLAY2 when it is on, else the first screen that is on (`kenshi-ctl.ps1 monitors`); the window is re-placed after the launch (Ogre moves it once more). Nothing in a batch may focus the game: input goes through `key_inject`/`mouse_inject` (isolation on), never `kenshi-ctl.ps1 focus` or a real key. Check after every launch with `kenshi-ctl.ps1 window` (monitor=DISPLAY2, foreground≠kenshi). **Shay before playing:** `gfx-mods.sh on` (now also restores full screen 2560x1440) or `kenshi-ctl.ps1 -Play`/`cfg play`; `cfg status` shows the mode.
  - **RAM commands:** voice services `wsl.exe -d DwemerAI4Skyrim3 -u root --cd / -- bash /mnt/c/KenshiModding/tools/automation/wsl-voice.sh <stt|tts|all> <start|stop|status>` (`wsl-restart.ps1` stops both after `/etc/start_env`; start `stt`/`tts` only for a voice/TTS batch, stop after). PocketTTS-off check 2026-10-04: replies arrive in ~1 s (vs ~2 s with TTS), the server's TTS call fails in ~2 ms with one `[WARN] Local TTS synthesis failed` per line (filtered from excerpts); the `NETWORK_ERROR 12002` lines in stobe.log occur with TTS on too. Graphics mods: `bash tools/automation/gfx-mods.sh off --hdtex` (Dust plugin + its effect DLLs/DLSS, ReShade `dxgi.dll`, HD detail textures: measured -2.6 GB private vs Dust/ReShade off alone; Kenshi closed) is the default for automated runs; **Shay before playing: `bash C:/KenshiModding/tools/automation/gfx-mods.sh on`** (restores all, incl. HD detail textures); `status` shows the state.
