- **Game-take discipline (Shay, 2026-10-10; kfx-b1/b2 lost takes to night, a missing RESULT line, an un-gated E6 take and a 1.5 h serial sweep):** (1) **Fail setup before filming:** every take script runs a preflight BEFORE recording: game time set + verified day, weapon ready (crossbow loaded = `fp_combat state` loaded>=1), open ground (clearance check), squad/area clean; one failed check stops that take with `RESULT <row> FAIL setup: <reason>`; never retry unchanged. (2) **Every wrapper prints exactly one `RESULT <row> PASS|FAIL <evidence>` line** (incl. takes that only record: PASS = recorded + its lab take checks passed); "no RESULT line" is a script bug, fixed before the next batch. (3) **Lab-gate every game take:** a pose/stroke set gets a game take only after it passes the animlab offline checks; if the lab passes and the game rec fails, log a lab Miss (lab fix) instead of refilming in a loop; no multi-try loops. (4) **Ready queue per rig:** `C:\KenshiTestRuns\queue\5090.next` and `4080.next` hold the NEXT batch for each rig (line 1 owner, then list path/steps, or `none: <reason>`), written before the current batch ends and replaced when it starts; the Stop hook blocks while one is missing or > 6 h old; `session-start.ps1` prints them. (5) **Short focused takes:** one weapon/mode/state per take (minutes, not an hour), each independently rerunnable; split long sweeps; a failure costs one short take. (6) **Two filming rigs:** the 4080 is a full second filming rig, not a side-job rig: take scripts run on both through the rig layer (`RIG=5090|4080`: launch/ctl, lock owner, fixtures, resolution, paths; recipe in `handoff/4080-test-rig.md`); both rigs run the same KenshiFP/harness build and refilms are split across them, two at once. (7) **The lab predicts the game:** fix offline first, a game take only confirms; every lab-vs-game disagreement and every review flaw the lab passed is a lab bug (Misses row + automatic check, owned by the standing animlab maintainer); keep the lab agreement report current. (8) **Review packs:** no video reaches the coordinator's review without `python3 tools/automation/review-pack.py <video> <out> --ts <ts.txt> --labels <labels.txt> --lab <lab/take check outputs>` (WSL): 1 fps sheets over the whole length + 8 fps sheets from t-0.5 to t+1 s at every recorded state switch and label, plus INDEX.txt with switches and lab results. The review stays complete (every 1 fps sheet + every switch sheet) but starts with no rendering pass; the builder sends the INDEX.txt path.

- **Viewmodel builds: zoomed-out check every build (Shay, 2026-10-09; hands-at-the-head and wrist-fold poses at zoom 25 went unnoticed until the final build):** every KenshiFP viewmodel build runs `fp-viewmodel.sh` row `VMQUICK` first (~3 min, one launch: every sword + crossbow animation at zoom 0 AND fp_camera distance 25, one labelled sheet + the automatic PT29 zoom-out checks: hand away from the head, weapon visible, wrist bend limit); the builder reviews that one sheet at full resolution before any long row or further iteration. Run VMQUICK on the 5090 while the 4080 runs the numeric rows in parallel. Never leave the zoomed-out review for the final build. **Sheets must be judgeable (Shay 2026-10-09: every sheet so far had the NPC jammed against a wall, animations invisible):** capture on open ground with nothing solid in frame (setup check fails the row otherwise), zoom-25 camera from the side/front, full 1600x900 frames; a sheet where the arm/weapon motion can't be clearly seen is rejected, never "reviewed".
- **Animation lab learns from the game (Shay, 2026-10-09):** the lab (harness `docs/animlab/USAGE.md`, phases 1-3 tagged `animlab-p1..p3`) is kept improving. Every time a fixer sees something in the game the lab missed or got wrong, it adds a line to "Misses" in `Kenshi-Automation-Harness/docs/animlab/STATUS.md` (date | point | what the game showed | recording | build | status). The standing lab maintainer (a helper running alongside the fixer) turns each miss into a lab check that fails on that recording, or records why it's out of reach. Before any video goes to Shay, its recording is replayed through the lab and every disagreement is logged as a miss. **Feedback loop (Shay, 2026-10-10):** (1) fix the CLASS, not the case: every Misses row names its failure class and the check covers the class (state checks judge every occurrence of the state; foreign-overlay check covers cursor/popups/stray UI; every stroke/pose table is compared lab vs game); (2) setup/take failures get their own "Setup misses" list, and each becomes a check in the shared take preflight that would have stopped it before filming; (3) a catch-rate ledger per build (found first by lab vs review vs Shay vs game rows, per class) shows whether the lab improves; (4) every check keeps a FAIL and a PASS recording in the protected corpus (`C:\KenshiTestRuns\corpus\`, never cleaned); (5) the whole corpus runs through all checks on every KenshiFP viewmodel build, before VMQUICK, so a fixed miss can't return; plus mutation tests (each check must catch synthetic corruptions of its kind), backfill (a new check runs once over all kept material), and review-verdict FAILs auto-append a pending miss. (6) Shay's accept/reject decisions (and, lower-weight, coordinator review verdicts) are a labelled "taste set"; the lab is scored against it per rule (Taste score in STATUS.md) and every disagreement is a miss; (7) spec first: every standing pose/presentation rule is a lab check (rule->check map in STATUS.md) BEFORE a new animation family (fists, kicks, ...) is built, and its first candidate is judged against them; inferred rules go to Shay as batched questions, not facts. Owners: `animlab-maintainer` (checks, classes), `animlab-loop` (corpus, gate, setup misses + preflight, ledger, mutation, backfill), `animlab-spec` (taste set, rule->check map, unarmed spec).
