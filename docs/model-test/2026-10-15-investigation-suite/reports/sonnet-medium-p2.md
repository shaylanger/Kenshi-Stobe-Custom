Summary
Both symptoms come from server code that matches on a name or a movement action without checking who the NPC is or what you asked for. I changed nothing.

1. The server gave this Tengu the Emperor Tengu profile because it looks up "unique character" biographies by name only. A plain "Tengu" row in the bio table is the emperor's biography.
2. The "I haven't agreed to that job" line was the server's own refusal, not Tengu's. The LLM emitted a move-toward-Shay action on its own, and a gate meant for player orders rejected it and overwrote her reply with the refusal text. You never ordered anything.

Root cause
- Issue 1: `loadBioUniqueTraitSelections()` in `lib/data_functions.php` (about line 5413) selects from `combined_bio_unique` where `LOWER(name)` equals the NPC's name or the name with any bracket suffix removed. `data/schema.sql` lines 3404-3408 seed five rows named plain `Tengu` (personality, backstory, speechstyle, occupation, goals) that describe the emperor. A separate `Emperor Tengu` set (11 rows) also exists. Race, gender and faction are never checked. `selectBioTraitsForNpc()` (about line 5676) uses these unique rows in preference to random ones.
- Issue 2: `stobeTravelValidateOrders()` in `lib/travel_companionship.php` (line 538) runs `stobePlayerOrderGate()` on every action the LLM emits. It does not check that the player asked for anything.
  - For a non-faction NPC, `MOVE_TO_TARGET` counts as a "minor order" (`lib/chat_helper_functions.php` line 15886).
  - Her affinity toward Shay was -5, below the minimum (`MINOR_ORDER_TRUST_MIN`, which defaults to `GIFT_TRUST_THRESHOLD`, 56).
  - `stobeTravelOrderGate` returns null (`lib/travel_companionship.php` line 378) because no travel deal is ACCEPTED, and its allow-list never includes `MOVE_TO_TARGET` anyway.
  - The function therefore falls through to `return "I haven't agreed to that job."` (`lib/chat_helper_functions.php` line 15925).
  - On a rejection, `travel_companionship.php` line 561 sets `$text = $why`, replacing whatever she was going to say.

What I ruled out
- Hand-edited or locked profile: `lock_profile` is false and there is no manual edit trail.
- Speech-to-text: it did make "Tengu" come out as "Tango" in your lines. That explains the odd "Emperor Tango" exchange, not the emperor identity.
- Real job or travel state: there was none. The log shows no travel proposal or ACCEPTED state, and no job action. The refusal text was produced by the gate, not generated by the LLM.
- Runtime or settings: nothing was changed there.

Proposed fix
1. Stop the emperor profile leaking onto other Tengus.
   - In `loadBioUniqueTraitSelections()` (and `selectBioTraitsForNpc`, which would pass race, gender and faction through), skip a unique row set when the NPC's known race, gender or faction contradicts it. The emperor is a Scorchlander male in the United Cities, and she is a female Shek in the Anti-Slavers.
   - The simplest data-only fix is to delete the five plain `Tengu` rows (`schema.sql` lines 3404-3408 and the live `bio_unique` table). The 11-row `Emperor Tengu` set stays. Check that the real emperor NPC is named `Emperor Tengu` in game before deleting.
   - If an emperor-named NPC is ever spawned as plain "Tengu", this fix would hide it.
   - Change `negotiation_phase1.php` line 370 to match `emperor tengu` only, or to require a bounty or faction check for plain `tengu`.
   - Her existing DB row keeps the emperor text until it is rebuilt: delete it or reset it so profile generation reruns. That write was out of scope here.
2. Stop the false refusal.
   - In `stobeTravelValidateOrders()`, apply `stobePlayerOrderGate` only when the player's line actually requested the action. A simple version drops a rejected `MOVE_TO_TARGET`, `FOLLOW` or `MOVE_TO` silently and keeps her original text. A tighter version passes the player's line in and checks it for a movement request.
   - Change `$text = $why;` so it is set only when the player gave an order. Otherwise keep the NPC's own speech and just drop the action.
   - Also stop the LLM from volunteering movement during idle talk, for example by not offering `MOVE_TO_TARGET` toward the speaker when no travel request was made.

How to confirm the fix worked
- Issue 1: after rebuilding Tengu's profile, `select occupation, backstory from core_npc_master where name='Tengu'` must no longer say emperor. Add a regression check for `selectBioTraitsForNpc('Tengu', 'Shek', 'female', 'Anti-Slavers')`. It should fail before the fix and return no unique traits after it. In game, greeting her should give no emperor claims.
- Issue 2: say "You are not Emperor Tengu" to a low-affinity NPC. No `Order rejected before speech` line should appear, and her reply must not be "I haven't agreed to that job". The same sentence must still reject a real order such as "follow me" from a non-faction NPC with low trust.

What is not settled
- Whether the model was prompted into `MOVE_TO_TARGET@Shay` by "I am walking. Walk with me", or by something in the system prompt. The raw LLM output is not in the logs.
- Whether other plain-name entries in `schema.sql` (for example `Esata the Stone Golem`) can collide with ordinary NPCs. I did not audit the full list.
- The DB row's created_at of 03:49 is on a different clock from the log's 01:51; I did not reconcile them. It does not change the cause.
