# Overlap ("tail") handoff: contract shared by all work packages (Shay approved 2026-10-15, directly in the coordinator session)

Goal: when a coordinator nears its context limit it does NOT exit. It opens a NEW coordinator session and stays alive as a TAIL session so its in-session subagents are not killed. In-session subagents (visible, accessible) are the standard again; the hidden agent-host is kept as code but no longer used for long work.

## Flow
1. Trigger: coordinator context ~300k, the context meter fires `handoff`.
2. Old coordinator (~3 min): (a) update testing/HANDOFF.md "Right now" + the program ledger; (b) for EACH running agent write a ledger routing note (purpose/brief, where output lands, what the new coordinator does when it finishes, dependencies, open decisions/warnings); (c) set each running agent's `owner_session` = `tail:<session>`; (d) run handoff-ready.ps1 and open the new session; (e) enter TAIL MODE by creating `C:\KenshiTestRuns\tail\<session>.flag`.
3. Tail mode: spawns nothing, edits nothing, decides nothing; keeps its waker for its own agents. When an agent finishes: save the full report to a file, send the NEW coordinator a message <= ~30 lines (key results, file path, patch/test locations, blockers/questions, pointer to the ledger routing note) AND write the same file to the new coordinator's inbox (`C:\KenshiTestRuns\inbox\coordinator\<ts>-tail-<agent>.msg`). Forward immediately and unchanged: agent questions/blockers, stalls, any peer message that reaches the old session. Stall rule: agent transcript (subagents/agent-<id>.jsonl) silent 10 min -> message the agent; silent 20 min -> TaskStop it and tell the new coordinator. Healthy agents run as long as needed. The tail ends itself after its last agent's result is ACKNOWLEDGED by the new coordinator. If the tail reaches ~400k first: remaining agents checkpoint (patch/status/handoff), are stopped, the new coordinator respawns them.
4. New coordinator: works at once from the handoff + ledger; never respawns agents the ledger shows owned by a LIVE tail session; acknowledges each relay (`tail-ack`); spawns the next work package when a slot frees using the routing note; treats tail messages as results, not orders.
5. Hooks: context meter quiet for a session with a tail flag; waker-guard Stop hook lets a tail session end only when its agents are all done and acknowledged and exempts it from idle-5090 / handoff-marker rules; only the live coordinator beats the heartbeat; supervisor + session-start list tail sessions and which agents they own, and flag a tail session whose process is gone together with its agents (those agents are dead: respawn from checkpoints).
6. Ledger fields per agent (in the work package record of `C:\KenshiTestRuns\programs\<program>.json`, `agents` map or per-wp `agent_records`): `owner_session` (`live` | `tail:<name>`), `routing_note`, `result_file`, `acked_by_new_coordinator` (bool).
7. COLD START (PC shutdown, everything died): `session-start.ps1` lists every ledger agent whose session is not alive as DEAD with the respawn line and its routing note; the fresh coordinator respawns them from their checkpoints (in-session subagents via the Agent tool, fresh names wpA -> wpA2).
8. Replaces the "do not touch independent sessions" handoff text and the drain idea. Router: the denial of long in-session agents is REMOVED (in-session is standard); spawn-wp-session/agent-host remain as code but are not used for long work by default.

## Relay follows the current coordinator; closing a finished tail (Shay 2026-10-15)
- **Pointer:** `C:\KenshiTestRuns\coordinator.current`, JSON `{session, pid, name, started, updated}` = the live coordinator. Written by `session-start.ps1` (`tail-mode.ps1 current set -Auto`: newest transcript id; never for agent sessions or a tail session) and corrected with the exact session id by the heartbeat claim in `coord-heartbeat.ps1`; read with `tail-mode.ps1 current`.
- **Relay target (`tail-relay.ps1`):** no `-ToSession` = the pointer session (process alive, not itself a tail). `-ToSession X` where X is a tail session (flag) or the dead pointer session = redirected to the current coordinator. Pointer missing/unreadable/dead/itself a tail = the old behaviour (inbox file only; `-ToSession` kept as given), then the flag's `relay_to` if set. The shared inbox file is always written; the last output line prints the chosen target and the reason.
- **Rule:** a coordinator that hands off while an older tail is alive re-routes that tail's agents (or acks them) first. `tail-mode.ps1 adopt [-Session <id>]` (run by every `session-start.ps1`) sets `relay_to` = the current coordinator in every LIVE tail flag; the ledger `owner_session` stays `tail:<id>` (only the target changes); `tail-mode.ps1 list|status` and session-start show it.
- **Closing (`tail-close.ps1 -Session <id> [-DryRun] [-DelaySec 20] [-NoRelay] [-Source manual|hook|ack]`):** when all of a tail's agents are done AND acknowledged: (1) it sends `TAIL-DONE <id>` (`tail-relay.ps1 -Kind TAILDONE`, inbox + target for SendMessage); (2) a detached worker waits ~20 s, re-runs every check, kills the tail's claude process tree and removes the flag. Checks (fail closed): flag readable; every agent done+acked (re-checked at kill time); pid exists and matches the flag's `proc_name`/`proc_start` (recorded by `enter`; older flags: claude/node and not younger than the flag); not the coordinator.current session/pid, not the heartbeat owner, not an ancestor of a manual caller; a flag with no agents closes only when older than 5 min. Log: `C:\KenshiTestRuns	ail\closed.log` (REFUSED, DRYRUN, SCHEDULED, CLOSED, ...). Triggers: the Stop hook tail branch when the tail may end; `tail-ack.ps1` after the last pending agent is acked (`-NoClose`, `-DryRunClose`); manual by the coordinator. Env `KAH_TAIL_NO_CLOSE=1` disables the kill (selftests).

## Interfaces (fixed so packages can be built in parallel)
- Tail flag: `C:\KenshiTestRuns\tail\<session>.flag`, JSON `{ "session": "<id or name>", "pid": <claude pid>, "created": "<iso>", "new_coordinator_inbox": "C:\\KenshiTestRuns\\inbox\\coordinator", "agents": ["<agent>", ...] }`. `<session>` = the Claude session id (from the hook JSON `session_id`); tools take `-Session <id>`.
- Scripts (all under tools/automation/, each with a selftest and `-SelfTest` flag or `*-selftest.ps1`):
  - `tail-mode.ps1 enter|status|leave|list -Session <id> [-Agents a,b]` (WP-T1): create/read/remove flags; `list` prints live and dead tail sessions.
  - `tail-relay.ps1 -Agent <name> -Report <file> [-Summary <text>] [-ToSession <id>]` (WP-T2): writes the <=30-line relay message to the new coordinator inbox and prints it for SendMessage; `tail-ack.ps1 -Agent <name>` sets acked_by_new_coordinator.
  - `program-ledger.ps1 route <program> <agent> -Owner live|tail:<id> -Note "<routing note>" [-Result <file>]` and `program-ledger.ps1 ack <program> <agent>` (WP-T2).
- Relay message format (first line is the key, file extension .msg): `TAIL-RELAY <agent> <DONE|FAILED|STALL|QUESTION|PEER> <iso time>` then `report: <path>`, `ledger: <program>/<wp> routing_note`, then <= 28 lines of key results / patch+test locations / blockers.
- Thresholds: handoff ~300k, tail hard limit ~400k, agent stall 10/20 min (read from a small JSON `C:\KenshiTestRuns\tail\config.json` if present, else these defaults).
